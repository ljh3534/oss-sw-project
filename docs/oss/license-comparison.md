# 오픈소스 라이선스 비교 분석 및 선택 기준

> 6주차 선택과제 — 주요 OSS의 라이선스를 비교하고, AdPrice가 MIT를 선택한 이유를 정리한다.

## 1. 라이선스 유형

| 유형 | 핵심 | 대표 라이선스 |
|---|---|---|
| **Permissive(허용형)** | 저작권 고지만 유지하면 수정·재배포·상용·사유화 모두 가능 | MIT, BSD-2/3-Clause, Apache-2.0 |
| **Weak Copyleft(약한 카피레프트)** | 해당 *파일/라이브러리* 를 수정하면 그 부분만 공개 | LGPL-2.1/3.0, MPL-2.0 |
| **Strong Copyleft(강한 카피레프트)** | 파생 저작물 *전체* 를 같은 라이선스로 공개 | GPL-2.0/3.0 |
| **Network Copyleft** | 네트워크 서비스로 제공만 해도 소스 공개 의무 | AGPL-3.0 |

## 3. 실제 OSS 사례 분석

| 프로젝트 | 라이선스 | 선택 배경 / 시사점 |
|---|---|---|
| **React** (Meta) | MIT | 2017년 BSD+Patents → MIT로 변경. 특허 조항에 대한 커뮤니티(Apache 재단 등)의 반발로, *채택 장벽을 낮추는 것*이 라이선스 선택의 핵심임을 보여 준 사례 |
| **Vite / Vitest** | MIT | 프론트엔드 도구 생태계의 사실상 표준. 의존성으로 쓰는 쪽에 부담이 없음 |
| **Kubernetes** (CNCF) | Apache-2.0 | 다수 기업이 기여 → **특허권 명시 허락**과 특허 보복 조항으로 기업 간 분쟁 위험을 낮춤 |
| **Linux 커널** | GPL-2.0 only | 파생물의 공개를 강제해 하드웨어 벤더의 드라이버 개선이 커널로 환류되는 구조 |
| **Firefox** (Mozilla) | MPL-2.0 | 파일 단위 카피레프트 — Mozilla 코드 개선은 공개시키되, 다른 코드와의 결합은 자유롭게 |
| **Grafana** | AGPL-3.0 (2021년 Apache-2.0에서 변경) | 클라우드 사업자가 소스 기여 없이 SaaS로 재판매하는 것을 막기 위한 *방어적* 변경 |
| **MongoDB / Elasticsearch** | SSPL 등 (OSI 비승인) | 오픈소스 → 소스 공개(Source-available)로 이동. "OSI 승인 라이선스인가?"가 선택 기준이 되어야 함을 보여 줌 |

## 4. 라이선스 선택 기준 (의사결정 트리)

```
Q1. 다른 사람이 내 코드를 사유 제품에 넣어도 괜찮은가?
 ├─ 아니오 → Q2. SaaS(네트워크 제공)까지 공개를 강제해야 하는가?
 │            ├─ 예   → AGPL-3.0
 │            └─ 아니오 → GPL-3.0 (전체) / MPL-2.0 (파일 단위)
 └─ 예   → Q3. 여러 기업이 기여하고 특허 분쟁 가능성이 있는가?
              ├─ 예   → Apache-2.0
              └─ 아니오 → MIT (가장 단순, 채택 장벽 최저)
```

추가로 확인할 것:

1. **의존성 라이선스 호환성** — 사용하는 라이브러리가 GPL이면 내 프로젝트도 영향을 받는다.
2. **OSI 승인 여부** — 승인되지 않은 라이선스는 "오픈소스"로 인정받지 못하고 기업 채택이 어렵다.
3. **조직 정책** — 회사·학교의 오픈소스 정책(허용/금지 라이선스 목록)을 따른다.
4. **향후 변경 가능성** — 기여자가 많아진 뒤 라이선스를 바꾸려면 모든 기여자의 동의(또는 CLA)가 필요하다.

## 5. AdPrice의 선택: MIT

| 기준 | 판단 |
|---|---|
| 목적 | 단가 산정 **기준점을 널리 퍼뜨리는 것** → 채택 장벽이 가장 낮아야 함 |
| 사유 제품 포함 | 대행사·광고 플랫폼이 계산 모듈을 내부 도구에 넣어도 무방 (오히려 확산에 유리) |
| 특허 | 단순 계산 공식으로 특허 이슈 가능성 낮음 → Apache-2.0의 특허 조항 불필요 |
| 의존성 호환 | React·Vite·Vitest·ESLint 모두 MIT → 충돌 없음 |
| 운영 부담 | NOTICE·변경 고지 의무가 없어 학생 프로젝트 운영에 적합 |

**재검토 조건:** 기업 기여자가 늘어나거나 계수 데이터셋을 별도로 공개하게 되면 *코드는 MIT, 데이터는 CC BY 4.0* 이중 라이선스를 검토한다 (ADR로 기록).
